# 参数扫描分析与决策 SOP（sweep-analysis）

本技能规定「一批扫描数据如何从表格变成**可辩护的参数决策**」。它是 `AGENTS.md` 红线 1、4 在扫描分析层的可执行化，
也是 `report-and-evidence`、`dataset-contract` 在"先筛参数、后做样本"这一环的落地。

**核心立场：没有几何/选择预检，排名只能是"临时"的；没有模型哈希，批次只能是"不可比"的。**

## 何时使用

- 用户给来一份扫描导出表（CSV/XLSX），问"哪组参数最好/下一步扫哪里"；
- 需要把粗扫结果收敛成 3–5 组精扫候选；
- 多批数据（换了模型/改了接线/改了网格）需要并排比较。

不适用：单点求解、文献数值抽取、实验数据接入——那些走 `dataset-contract` / `report-and-evidence`。

## 0. 三条口径铁律（先记住，后面全部依赖它）

1. **幅值用 `20*log10`，功率用 `10*log10`，绝不混用。** 混用会凭空造出 2 倍 dB 差异。
2. **`−6 dB` 交点在相邻频点间线性插值；曲线在频段边界仍未回落 6 dB 时必须标 `lower_bound_not_found` /
   `upper_bound_not_found`，禁止把边界当交点。** 若多数组合的峰值落在频段上边界（实测曾出现 31/70 组合峰值落在 35 MHz），
   说明**谐振没被频段包住** ⇒ 该批数据不得用来选"最优参数"，只能用于筛掉明显差的组合。
3. **命名限制：** 只能说 `Vave` 是**响应**−6 dB 带宽、`Ptot` 是**功率**−6 dB 带宽。
   **禁止**称"往返带宽/脉冲回波带宽/阵列带宽"——单 PMUT 单元模型不支持这些说法。
   最终主判据是 7R 轴向声压 `H_p(f)=|p(f,0,0,7R)|/|V|`（`7R = 294 µm`，坐标原点须平移到膜中心），
   该量未算出之前，只能以 `Ptot`（功率带宽）与 `Vave`（响应带宽）**并列**筛选，不得合成单一总分。

## 1. 第一步：冻结输入并哈希（没做这步，后面全部白做）

对每批数据记录 **sha256**：导出表、（若可得）模型 `.mph`、生成该模型的 `.m`、决策/指令文档。
- 哈希写进一个 `freeze_inputs.json`（落 `work\reports\<批次>\`），字段含 `path/bytes/mtime/lock_present/sha256`；
- **带 `.mph.lock` 的模型不取哈希**（GUI 打开中，内容是未保存状态，取了就是假证据），写 `note` 说明"跳过原因"；
- 目标模型一律**只读引用**，绝不在原地改。

## 2. 第二步：数据质量检查（先于任何计算）

对导出表逐项核验并在报告里写明数字：
- 行数 / 组合数 / 频点数；**每个组合的频点数是否一致**（缺行必须查明原因，**禁止插值补齐**）；
- 空值、`NaN`、`Inf`、无法解析的复数 → 计数；
- 频点是否严格递增（拟序）；
- 物理量符号：如 `Ptot` 出现负值 ⇒ 先怀疑积分面法向，**只标记不取绝对值**；
- 冗余量一致性：若两个公式等价的量逐位相同（实测 `Zin1 ≡ Zin2`，二者都写成 `v0/I01`），
  ⇒ **已知公式缺陷，修正前不参与评分/排名**；
- 网格覆盖性：对照 `.m` 里批处理的 `plistarr` 与实际出现的组合，**逐一列出缺失点**。

## 3. 第三步：几何/选择预检（决定排名资格，唯一需要 COMSOL 的一步）

```powershell
python scripts\geometry_selection_precheck.py --model "<被扫模型>.mph" --xs <a:step:b> --n1 <a:step:b>
```
- **只建几何 + 网格，不做频域求解**，逐组合读实际生效的边界实体并量取面积，分类落档：
  `clean` / `N0_control` / `empty_selection` / `bc_conflict` / `geometry_failed` / `mesh_failed` / `area_anomaly`；
- **网格参数必须取自该批数据的实际网格**（见 §6 第 1 条）。若预检网格与数据网格不一致，
  会得到"预检子集 ⊄ 数据子集"的结果，排名无法对齐；
- 分类语义：`bc_conflict` 表示**两个选择包络相交**，**不等于**实体电极几何无效
  （`cyl8`/`cyl9` 这类更可能是"圆柱选择工具"）。因此只标 `selection_or_bc_suspect`，
  判"几何无效"必须由实体边界交集/面积证据支撑；**修正方式是"由最终缩放几何派生命名选择集"，不是把半径乘个比例**；
- **单实例红线**：该步要 COMSOL 许可证。GUI 或队列正在求解时**不许抢**，等空闲再跑；若源模型是数 GB 级，
  先确认可用内存（GUI 曾占 10.8 GB），或先用小模型试跑确认流程与耗时。

## 4. 第四步：分析与排名

```powershell
python scripts\analyze_sweep.py --csv "<导出表>" --out-dir work\reports\<批次> `
  --precheck work\runs\<预检 run>\geometry_selection_precheck.json `
  --batch-label <批次名> --model-file "<模型>.mph" --model-sha256 <sha256> `
  --model-version <三分法之一> --drive-mode "<驱动口径>"
```
产出：`00_provenance.json`、`01_cleaned_results.csv`、`03_coarse_sweep_metrics.csv`、
`04_pareto_candidates.csv`、`05_fine_sweep_plan.csv`、`06_final_comparison.md`、`figures\`。

排名规则（不可协商）：
- **只在预检 `clean` 的子集内排名**；`N0_control`（如 `N_w_te1=0` 的单电极对照）**单列**，不进双电极主排名；
- **未提供预检文件 ⇒ 所有排名显式降级为"临时"**并在报告首行声明；不得把临时排名当结论；
- **不做无依据的单一加权总分**：改为多指标 top-N + Pareto 非支配前沿（如 FBW↑、`Vave@20MHz`↑、`Ptot@20MHz`↑、平坦度↓）；
- 精扫候选按"角色"选取并写明理由（基准点 / 带宽上下界均被包住的最宽组 / 与基准显著不同的组），
  标准精扫为 **5–40 MHz @0.5 MHz = 71 点**。

## 5. 第五步：多批次绝不混排（红线 4）

每批必须携带：`batch_label`、`model_file`、`model_sha256`、`model_version`、`drive_mode`、`source_csv_sha256`。
- `model_version` 三分法：`original_selection_original_drive` / `corrected_selection_original_drive` /
  `corrected_selection_explicit_reverse_drive`；
- 未提供 `--model-sha256` 时脚本会告警：**该批禁止与其它批次合并排名/合并统计**；
- 多批比较的正确姿势是**并排**（各自出 `03_`/`04_`，再做对比表），不是把行拼在一起；
- 修正模型产生的新数据**单独入库、单独排名**，与旧批并排展示差异。

## 6. 实测踩坑清单（都真实发生过，别再踩）

1. **预检网格要用"数据实际网格"，不是别人假设的网格。** 实测同一模型存在两套口径：
   `.m` 批处理节点 `plistarr={'range(0.1,0.1,1)','range(1,1,8)'}` = 80 组合，
   而外部指令假设的是 `x 0.4:0.05:0.8 × N1 0:1:8` = 81 组合。**先读 `.m` 的 batch 节点，再决定 `--xs/--n1`。**
2. **读 `.m` 参数必须取"最后一次 `param.set`"。** COMSOL 导出脚本会在**文件末尾**再覆盖一次参数
   （实测 `N_w_te2` 在 L78/L157 写 `5`、在 **L2389** 覆盖为 `9`，紧接 `geom.run('fin')`，运行态真值是 9）。
   用 `Select-String | Select-Object -First N` 截断输出会读到**失效的历史值**并得出错误结论。
3. **频点索引映射 ≠ 求解顺序。** `evaluate('freq')` 的顺序可能与 `inner=[i]` 的索引顺序不同
   （实测出现旋转：`inner[0]` 对应 35 MHz），逐点取数必须**按频率值回填**，并用单点独立求解抽验。
4. **控制台编码会打断整条管线。** Windows 控制台多为 GBK：脚本往 stdout 打印 Emoji 会 `UnicodeEncodeError`
   直接崩（写文件不受影响）。管线里应对 stdout 做 `errors="replace"`，或输出用 ASCII 标记。
5. **COMSOL 启动器在受限文件策略下静默失败**（`rc=15`、无输出、无产物）——不要误判成模型或代码问题，
   见 `AGENTS.md` §3。
6. **别把"量级正常"当成"物理正确"。** 面积/功率量级正常但选择集张冠李戴的情况，只有实体预检能发现。

## 7. 交数据/交结论时该给什么

给数据方（用户）需提供：每批导出表路径（**不覆盖旧表**，旧表是基准批）、每批对应模型文件（且**未被 GUI 锁定**）、
Batch/求解日志（用于判定缺失组合是"列表被覆盖"还是"求解失败被静默跳过"）、若改过接线则说明改法。

出结论方（智能体）必须随结论声明：数据批次与哈希、模型版本与驱动口径、预检分类、频率范围与步长、
`−6 dB` 是否为插值估计、哪些量被排除及其原因（如 `Zin2`）、以及**"本结论不外推到阵列性能"**。

## 8. 取值逐位复现（R5）与扫频缝检测（R6）：分析侧条款

> 完整条款分别在 `dataset-contract` §10（精确取值台账）与 `comsol-batch-production` §9.4/§9.5
> （缝检测、采样充分性）。本节只记**分析侧必须跟着做的三件事**，避免技能之间各自漂移。

### 8.1 排名前先确认取值口径逐位一致（R5）

- 台账里的精确取值（如 `x_scale=0.24000000000000002`）与分析表里的字面值不一致时，
  **不得把两批当成同一参数点**：先判「是同一个点还是两个点」，再决定能否并排；
- 精扫候选与粗扫结果对不上时，先查 **1 ulp 级**的取值差异（实测 `0.24` vs
  `0.24000000000000002` 造成 **0.009 dB** 差），再怀疑物理或驱动；
- **组合身份键一律先做 ulp 归一化**（浮点参数 `round(x, 6)`）再判等。实测代价：2026-10-08
  两批数据因 `x_scale` 的 1 ulp 表示差（C 批 `0.30000000000000004` / v2 批 `0.3`），
  把 v2 相对 C 的**新增数从 83 误报成 117（虚高 34）** —— 见 §92 与
  `scripts/recount_v2_newness.py`。**这个错误的方向是"虚报产出"，最容易被当成好消息放过。**

### 8.2 分段扫频必须做缝检测（R6）

- 输入频点表是**拼接**而成（如 5–50 与 52.5–80）时，先跑**缝检测**（母版
  `work/runs/stage1-20261008/seam_diagnostic.py`）：报出**未采样区间**，
  并在报告里标记「首峰可能藏在缝内」；
- 实测后果：`x=0.28` 族首个局部极大正好落在 **50.0 ↔ 52.5 MHz** 的缝里 ⇒ Stage-1 首轮只能给
  **空标签**（不外推）；缝内补扫后该族才由「空标签」转为进 Stage-2。
  ⇒ **不补这一缝则既看不到也判不了**；
- 缝内补扫属**计划变更**：预注册 → 人裁决 → 带锚点补扫，**不得默认执行**（见 §5 多批次纪律）。

### 8.3 采样充分性必须随排名一起报（R7）

- 报排名时同时输出**每半宽点数**与**峰位是否落在网格点上**；两者不足则只报「方位与闭合性」，
  **不报精确峰位/带宽**（实测候选峰每半宽仅 1.5–2.7 点）；
- 判据在评估规模上**不可达**时按 `inconclusive` 处理，**不得记 failed**，更不得记通过 ——
  语义见 `ai-solver-verification` §7。

### 8.4 跨管线标签**只能并置，不能池化**（2026-10-08 实测）

两批（C 批 5–50 MHz / v2 批 5–35 MHz）在 **167 个组合上重叠**，据此做了跨管线一致性对账
（`scripts/cross_pipeline_label_check.py`，只比 v2 未删失/未截断的组合；**描述性、无通过线**）：

| 量 | 可比组数 | 中位相对差 | 超 5% | 最大 |
|---|---|---|---|---|
| 峰值频率 | 100 | **0.000e+00（逐位相等 69/100）** | 31/100（其中 30 组超 100%） | 3.467× |
| 带宽 | 100 | **30%** | 97/100 | 4.699× |
| Q | 76 | **19%** | **68/76 = 89.5%** | 1.040× |

**必须据此执行的纪律**：

- 峰频逐位相等的那 69 组说明两批**同源**；剩下的是**多峰谱下「首峰 vs 最大峰」的选峰差异**，
  **不是数值误差** —— 不要把两者混成一句「两批不一致」；
- **即使峰频逐位相等，带宽与 Q 仍系统性不一致** ⇒ 这是 **−3 dB 截断点提取方法本身的差异**，
  **扫描范围解释不了**；
- **Q∈[2.5,3.5] 直接决定 `ranking_eligible`，而 Q 有 19% 中位差** ⇒
  **同一物理组合会因出自哪条管线而进出 Q 门槛** ⇒
  **任何基于 Q 门槛的排名或通过率必须标注管线来源**，且两批**不得合并池化/合并统计**（§5 红线）；
- 两批存在重叠组合 ⇒ **`batch` 不能直接当防泄漏的整组切分键**（同一组合会跨组）；
  须先定去重规则（**待裁定，不得自行执行**）；
- 「两批一致」在裁决出哪条管线的提取更正确之前，**不构成独立佐证**。

### 8.5 「整列为空」的批不得算通过（R15，2026-10-08 实测）

跨批表里常见一种**假通过**：某批的原始标志列（如 `peak_at_scan_endpoint`）**整列为空**、
另一批有值 ⇒ 检查项整体可求值 ⇒ 空列里扫不出违规 ⇒ 判 **PASS**。实测：并集表 v3 里
`C_5-50MHz` **1782** 行、`A_5-35MHz` **223** 行该两列**全空**，`V2_5-35MHz` **250** 行有值。

- **逐批**核可得性：某批的标志列**整列为空** ⇒ 该批**无法复验** ⇒ 该项判 `inconclusive`
  （`passed=None`），**不是 PASS**，**也不是 failed** ——「判不了」≠「不达标」，
  完整语义与用例见 `ai-solver-verification` §7 与 **§10**（该处是这条纪律的母条款）；
- 报门禁/报排名时必须同时给**逐批** `n_flag_nonempty` 与 `n_rows`，使「哪一批判不了」一眼可见；
- **本轮实测后果**：并集表 v3 与补列视图的 `batch_censored_not_eligible` 由 **PASS → inconclusive**。
  这**不是**「门禁变化导致通过/不通过」：**没有**任何检查项由 failed 变 passed，结论方向未变
  （`worst_verdict` 仍 `inconclusive`、`release_allowed` 仍 `false`、退出码仍 **4**）。
