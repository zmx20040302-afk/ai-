# 场 I/O 契约

## 1. 为什么必须先定公共点集

几何尺寸一变，网格就变，快照节点**天然对不上**——POD/逐点比对都无从谈起。
唯一可行做法：把每次的场**插值到同一套固定点集**上，使各次快照**等长、同坐标**。

**实测结论（P1 验证）**：公共点集固定 713 点；材料参数变化与**几何变化（重建几何+网格）后快照均等长**。

## 2. 导出路线（实测取舍）

| 路线 | 结论 |
|---|---|
| **✅ Python 侧插值（采用）** | 用已实测可用的求值 API 取**节点坐标 + 场值**，在 Python 里 `scipy.griddata` 插值到公共点集。与 COMSOL 版本/导出属性名解耦，几何变化天然支持 |
| ❌ COMSOL Grid 数据集 + Eval | Eval 数值节点**拒绝** Grid 数据集（"数据集类型无效"）——Grid 只服务绘图/导出 |
| ❌ Interp/插值数据集 | 在 batch/API 上下文**无法创建**（"在这个情景中不能创建本操作"） |
| ❌ `Export(location=grid)` | `location` 能设成 grid，但网格定义不生效（导出 **0 节点**）；属性族还随版本变化 |

## 3. 掩膜（硬性要求）

几何缩小后，公共点集里会有点落到域外 → **NaN**。处理规则：

- **公共掩膜 = 在所有快照中都有限的点**（`pod.common_mask`）；
- POD 基、系数拟合、误差统计**只在掩膜点上进行**；
- 预测时域外点**不得输出数值**；
- 绝不允许把 NaN 当 0 填充——那会污染基与误差。

实测：几何缩小后有 92/713 个点变 NaN。

## 4. 存储与命名

- 快照：`work/exports/*.npz`（或 Parquet），**必须同时保存公共点集规格**（每轴 start/stop/n）与显式坐标文件 `pod_points.txt`；
- 每个快照必须能回溯到 `run_id`（哪次求解）与抽取器版本；
- 单位：内部一律 SI；坐标与场量单位写进元数据（`x,y,z` = m；`T` = K；`u` = m；`p` = Pa）。

## 5. 场级误差定义（S1）

```
rel_L2 = ‖pred − true‖₂ / ‖true‖₂     # 只在掩膜点上、且双方都有限
```
- 必须**逐留出快照**给出，并报 **max**（不看平均值掩盖最差点）；
- 不得用"整场绝对误差"替代——量级不同的场之间不可比；
- 阈值：关键区域 < 2%，全域 ≤ 5%（WORKING_PLAN 6.1.1）。

## 6. 与 S3 的接口

场解取出后应直接跑 `scripts/check_s3.py` 做物理一致性检查（守恒/边界/对称），
**S3 不过则本次场解作废**，不得进入训练集、不得用于放行。

## 7. 常见坑

- `model.evaluate()` 返回**数组的列表**，必须 numpy 展平；复数先 `np.abs`；
- 同一 `.mph` 反复加载会持有文件锁 → 复制副本时按次递增命名；
- 公共点集必须**在接入阶段就定义好**（`model-onboarding` 第 8 步）并写进 `device_spec`，不要每次都重算。
