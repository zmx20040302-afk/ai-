# COMSOL 批量生产运行 SOP（comsol-batch-production）

本技能规定「**怎么安全地真跑一批 COMSOL**」。它是 `AGENTS.md` §4 执行约定的可操作化，
与 `freeze-and-acceptance`（冻结与验收）、`sweep-analysis`（跑完怎么分析）、`report-and-evidence`（数字怎么留痕）配套。

**核心立场：没有冻结不许跑；没有最小执行不许批量；失败必须能自证原因。**

## 1. 三条开工前置（缺一不许开跑）

```text
1. 代码已冻结：work\tools\freeze_snapshot.py --create 生成 freeze_id，且 --verify 为 MATCH
2. 已做过最小执行：真正调用过被改动的路径（不是静态检查），并留下命令/exit code/日志哈希
3. 资源达标：端口空闲、无其它 server、可用物理内存与 commit 均过门禁（见 §3）
```

**为什么最小执行是硬前置**：本机实测过一次教训——静态自检（grep）全部通过，但真实执行第一行就抛
`NameError`，整批空跑。**修复本身也需要被验收。**

## 2. 一次跑什么、跑多久（本机实测口径）

| 项 | 实测值 |
|---|---|
| 一个组合 × 7 频点（5–35 MHz） | 求解 **约 763 s**，加装模型/划网格/存档/清理 ⇒ **约 13–14 分钟** |
| 72 组合 × 7 频点（504 点） | 一组合一实例约 **15–17 小时**（过夜级） |
| 物理内存 | 32,189 MB；11 GB 级模型峰值 WS ≈ **11.2 GB** |
| commit 余量（页面文件 12 GB 后） | 求解平台期约 **8.7–10.1 GB** |

**一组合一实例**是默认（组合间互不污染，已真机验证）；共用实例更快，但**必须先做「两组合共用一个实例」试验**证明不累积内存。

## 3. 门禁与停止线

```text
前置（**2026-09-14 统一收紧**）：端口空闲 / **无 COMSOL 家族进程**（comsolmphserver / comsolbatch /
  comsolcompile 在场即拒绝启动；ComsolUI 用户 GUI 在场**允许**，但必须记录并在报告里声明）
  / 可用物理 ≥ **18000 MB** / commit 可用 ≥ **21500 MB** / **开跑前连测两次**（两次都须通过）
  —— 原 16384/16384 已废弃：实测 r3e 启动时 18,754 / 24,347（**高于**旧门禁）仍在 5 秒内被
     外部消费者阶跃吃掉 ~6 GB commit（掉到 0.5 MB）⇒ 旧门禁不足以保证平台期安全。
     命中进程清单（pid / name / start）必须写入产物，使「开跑时环境干净」可被第三方复核。
```
停止线（唯一权威：`work\tools\rt_gate.py` 的 `Thresholds`，**不得在别处复制一套**）：
`ws_warning 11500` / `ws_hard_stop 12288` / `physical_avail_hard_stop 4096` /
`commit_warning 6144` / `commit_hard_stop 4096`（均**连续 2 个 5 s 采样**）；连续 **15 s** 无新样本 ⇒ 停止投递并报警。

- **软线只阻止下一组合**；**硬线**先正常取消，必要时才终止**已核对归属**的 server；
- **`PeakWorkingSet` 单调不减，只作审计**；实时量看 `WorkingSet`；
- **"commit 余量低"不是故障前兆**——页面文件过小时它是本机常态。

## 4. 执行期必须做的事

```text
· 单实例串行；长任务走后台作业，禁止同步等待
· 每组合一个全新进程/实例（绕开"MPh 单会话单 client"约束，已真机证实 parent_is_worker=true）
· 运行前记录 LT2-C 类快速门禁：选择集非空、两两电极无交叠、控制面签名(area/bbox)、term1/cir 状态
· 先原子写 checkpoint，再关 server
· 每组合独立证据目录（child/attempt 级），禁止覆盖前一组合的时序
· 实时判定（每轮读 verdict + reasons + cancel_requested + 监控健康），禁止事后回放
· 终止前必须核对归属：端口 owner PID + 进程启动时间 + run-id 三者一致，不一致即拒绝终止
· 终止后二次确认：PID 消失 / 端口关闭 / 无意外新进程 / 终止命令退出码
```

**正常完成守卫**：`stage==closed` 或 checkpoint 已存在 ⇒ **不触发** enforce，等自然退出；
但**必须**保留例外——`verdict=="hard_stop"` 时守卫立即失效（真实越线永不被降级）；
抑制须**有界**（本机 60 s），否则会把监督器永久挂住。

## 5. 跑完要交的证据（缺一即不算完成）

```text
run_id / 命令 / 起止时间 / exit code
逐条判据取值（行数与唯一频率、驱动失配、solve_error、门禁、硬停与预警采样数、内存最低值）
checkpoint 有效性与容差证据（冻结值 vs 当前值 vs 相对差 vs 容差 vs 冻结证据 run_id+sha256）
身份证据链（pid_source / PID / start_filetime / parent）
清理证据（server 消失 / 端口 30 s 内关闭）
运行前后各一次冻结校验（source-vs-manifest 与 snapshot-vs-manifest 四项均 MATCH）
完整日志落盘 + 每份日志的 bytes/SHA256（**tail 只能预览，不得作为唯一证据**）
```

## 6. 失败分类：不许把基础设施故障说成资源故障

```text
resource_hard_stop  **只能**由"活着的监控真实产出连续越线样本"推导
禁止由：sidecar 退出 / 无样本 / 任务启动失败 / 目录复用被拒  推导为资源硬停
读失败或无数据 ⇒ 判 False（fail-closed），不得当"通过"
```
**为什么**：基础设施 bug 一旦被贴上资源标签，就会在生产里**掩盖同类 bug**（本机实测踩过：13:04 那次回归被误标成资源硬停）。

## 7. 本机实测的坑（照着避）

```text
1. 别只留 stdout 末几行——失败断言会丢（本机曾因此丢失一次失败的原始证据，永久无法复算）
2. 子进程 stderr 不要 DEVNULL——本机曾因采样器 rc=2 而无法诊断，逼得专门写复现器
3. os.replace 在 Windows 上遇"目标被读取"会抛 WinError 5 ⇒ 原子写必须有界重试且失败仍致命
4. 不要用 OpenProcess 判存活（父进程持句柄时恒成功）⇒ GetExitCodeProcess == STILL_ACTIVE(259)
5. 终止后不能只查一次 ⇒ 带超时轮询并留痕 waited_s/timed_out
6. 只读目录也要防 __pycache__ ⇒ 运行加 -B 且 PYTHONPYTHONPYCACHEPREFIX 指到输出目录
7. 输入参数分隔符要加固：曾出现"7 个频率被静默解析成 1 个" ⇒ 解析结果必须写入产物，数量不符即拒绝启动
8. Get-ChildItem 对正在写入的文件可能报过期 size（0 B）⇒ 不得据此判断文件为空
9. 文件名不等于内容（本机实测：名为 …fmax45 的模型与原始模型哈希相同）⇒ 用 API 实测，不凭名字
10. 同尺寸 ≠ 同内容；同后缀的相似文件名（差一个连字符）是两个文件 ⇒ 任何"等同"断言必须当场实测两侧
```

## 8. 绝对不许做

```text
· 不许在未冻结/漂移的代码上跑批量
· 不许为了让批次通过而放宽阈值、静默丢弃失败、或修掉被测对象里的断言
· 不许复用或清理既有 run 目录（历史失败现场永久保留，append-only）
· 不许靠耗尽真实内存来触发保护机制
· 不许手工 kill 去"把演练做出来"——归属核验拒绝终止时，那是保护生效
· 不许把"跑很多次没复现"当作竞态已修好的证据（要构造出必然触发窗口）
· 不许在没有实时中止机制的情况下跑无人值守长批次
```

## 9. 自动化要求 R1–R12（2026-10-08 求解自动化轮 · 逐条落地）

> 来源：`docs/INJECTION_SOLVER_AUTOMATION_MERGED_20261008.md` §4（每条都带 run 证据）。
> 本节**只追加**，不改动 §1–§8 既有条款。R4 → `field-io-contract` §8；
> R5 → `dataset-contract` §10 与 `sweep-analysis` §8；R3/R8 的验收侧 → `freeze-and-acceptance` §10；
> R12 的报告侧 → `report-and-evidence` §8。

### 9.1 R1 提交前预检：设了不报错 ≠ 能跑

- **现象**（有 run 证据）：`plistarr` 用**字符串**设值在 `set()` 阶段「成功」，`study.run()` 才抛
  `FlException: Syntax error in expression`；**任何含 `;` 的字符串形式都失败**，包括与模型原值同形者。
- **要求**：凡「设了不报错、跑起来才炸」的属性，一律在**求解前**用**与求解器同一条解析路径**
  复读校验（本例 `getDoubleMatrix('plistarr')` 并核对**每参数取值个数**）；不过即**拒绝提交**。
- **落点**：通用 launcher 模板的「提交前」阶段；预检取值必须写进 run settings，
  否则事后无法证明「当时检过」。

### 9.2 R2 fail-closed：退出码必须绑定**用例级**结果

- **现象**：驱动第一版**有用例失败仍打印 `STATUS=ok` 并从 0 退出** ⇒ 把失败报成成功。
- **要求**：驱动**逐用例计数**，收尾任一如失败即**非零退出**；
  launcher 的退出码绑定**用例级**结果，**不是**「进程活没活」。
- **落点**：launcher 模板 + 验收脚本（见 `freeze-and-acceptance` §10）。

### 9.3 R3 元数据与终态自洽：先落终态、再算清单

- **现象**：启动器**先算产物清单、后写终态** ⇒ `output_manifest.tsv` 里 `status.txt` 的哈希是
  中间态 `hashing_outputs`，与终态 `complete` 不符（run `stage1_n2_5/6/7`）。
- **要求**：**先写终态，再算清单**；此类**已定性的顺序缺陷**显式分类留痕 ——
  既不静默放过、也不误报成数据问题。
- **落点**：launcher 模板的写入顺序；验收侧见 `freeze-and-acceptance` §10.1。

### 9.4 R6 扫频计划必须自带「缝检测」

- **现象**：冻结频点表在 **50.0 ↔ 52.5 MHz 之间没有采样点**，而 `x=0.28` 族首个局部极大
  **恰落此缝内** ⇒ 位置不可分辨（不补这一缝则既看不到也判不了）。
- **要求**：对任何**分段扫频**（拼接而成的频点列表）自动报出**未采样区间**，
  并标记「首峰可能藏在缝内」；缝内补扫属**计划变更**，须走裁决
  （预注册 → 人批准 → 带锚点补扫），**不得默认执行**。
- **落点**：扫频计划校验（母版 `work/runs/stage1-20261008/seam_diagnostic.py`）；
  分析侧口径见 `sweep-analysis` §8.2。

### 9.5 R7 采样充分性：每半宽点数 + 峰位是否落网格 ⇒ 限制结论强度

- **现象**：候选峰 −3 dB 左半宽 3.66–6.63 MHz，而网格步长 2.5 MHz ⇒ **每半宽仅 1.5–2.7 点**。
- **要求**：判读输出必须含**「每半宽点数」**与**「峰位是否落在网格点上」**两项，
  并据此**限制结论强度**：只报「方位与闭合性」，**不报精确峰位/带宽**。
- **落点**：判读脚本；判定语义见 `ai-solver-verification` §7（判不了 ≠ 不达标）。

### 9.6 R8 回传即校验：逐文件比对哈希，豁免须显式声明

- **现象**：取回产物时发现「清单有、本地缺」与「哈希不符」（后者实为 R3 的先算后写）。
- **要求**：回传后**逐文件**对 `output_manifest.tsv` 比对哈希；
  **任何豁免必须显式声明并带原因**，不得让「漏扫」变成隐形放行。
- **落点**：取回工具（母版 `work/runs/stage1-20261008/verify_exports.py`）；
  验收侧见 `freeze-and-acceptance` §10.2。

### 9.7 R9 监视器要有明确退出条件 + ssh 统一 utf-8

- **现象**：监视脚本初版因 `cat` 报错被当作「非空 exit」⇒ **第一轮就误判完成**；
  收尾时本地 GBK 解码远程 UTF-8 中文而崩。
- **要求**：退出条件**三选一且明确** —— 终态 / 失败 / 停滞；**所有 ssh 调用统一
  `encoding='utf-8', errors='replace'`**；`exit_code` **只认纯数字**（非数字不得按 0 处理）。
- **落点**：`watch_run.py` 类模板。

### 9.8 R10 远端脚本一律「文件 + `bash -s`」

- **现象**：内联 ssh 传复杂引号被层间拆词（`-np` 收到 `"8,"` ⇒ COMSOL 报
  `Improperly specified VM option`）。
- **要求**：**禁止内联复杂引号**；远端脚本一律「**文件 + `bash -s`**」；
  生成的 shell 脚本保持**纯 ASCII + LF**（编码与换行本身也会变成故障源）。
- **落点**：`docs/REMOTE_EXECUTION_SERVER.md` §4/§8；模板随 launcher 分发。

### 9.9 R11 LiveLink 返回类型分支要写进工具函数

- **现象**：LiveLink 标签数组是 `java.lang.String[]`，`cellstr()` 直接失败；
  `getDoubleMatrix` 的**返回类型随形状而变**（cell / 3×1 double）。
- **要求**：提供**健壮的 LiveLink 工具函数**（`toCell`、**双类型预检**）并随模板分发，
  不要求每个调用方各写一份 try/catch。
- **落点**：`docs/REMOTE_EXECUTION_SERVER.md` §8。

### 9.10 R12 不变式披露机器化

- **现象**：「只改扫频范围」实际还需要**缩小外层取值**（笛卡尔积 81×7 → 所需几个），
  而摘要里只写了「改扫频」。
- **要求**：驱动须在摘要里**逐条打印**「改了什么 / 没改什么 / 缩了什么」并落入 run settings；
  明确 **「缩外层取值 ≠ 改物理」**（每个外层取值是一次独立求解）。
- **落点**：驱动模板；报告侧同款条款见 `report-and-evidence` §8。
