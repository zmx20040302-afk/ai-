## 4. 顺带抓到的**真 bug**：隔离标记被静默丢弃

`csv.DictWriter(..., extrasaction="ignore")` 会**无声吞掉**未列入 `cols` 的键。
`quarantined`（隔离标记）正是如此 ⇒ **表里根本没有这一列**，隔离信息全丢，且无任何报错。

修复三层：

1. 把 `quarantined` 显式列进 `cols`；
2. 构建脚本加 **fail-closed 断言**：任何写进记录却不在 `cols` 的键 → 直接报错退出，
   **不依赖人眼**发现静默丢列；
3. 固化为用例（静态检查该守卫存在）。

修复后隔离行 **4 个** = `(x=0.2, N1=1, N2=7)` 与 `(x=0.2, N1=1, N2=8)`，A、C 各一行。

## 8. 诊断脚本自身故障（一并修好）

`page_runtime_check.mjs` 本轮连报两类**假 FAIL**，均为脚本问题：

| 现象 | 真因 | 修复 |
|---|---|---|
| 所有 `onclick` "未绑定"、`window is not defined` | 页面已使用 `window.addEventListener` 捕获全局错误，而桩**没有 `window`** ⇒ eval 顶层即炸。**该脚本自那时起一直是坏的** | 桩补 `window`/`addEventListener`；Node ≥21 的 `navigator` 是只读 getter ⇒ 改 `Object.defineProperty` |
| `location is not defined` ⇒ 面板全空 | 页面用 `location.origin` 做多源回退 | 桩补 `location`，且 `origin` 必须 === `BASE`，否则绝对 URL 会被 fetch 转发拼成畸形串 |
| 「预测处理器没有产出」FAIL | 旧版用**空输入**点按钮，前端**正确地**拒答，而旧版只认 3 种措辞 ⇒ 把正确的 fail-closed 行为报成失败 | 改为**分别验两条语义** |
