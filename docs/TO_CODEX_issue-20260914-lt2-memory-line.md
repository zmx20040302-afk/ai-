**方案 A（推荐）：改线 + 分批重启**
- 把 LT2-D 的单批停止线改为与**求解工况**匹配的值，例如
  `peak_server_ws_mb < 12000`（或 `working_set_mb < 6000`），并**保留**"连续两个组合同类错误/端口不关闭/键重复缺失"等其余停止条件；

## 5. LT2 规模重估（据 LT1 实测）

- 单组合 **3 频点**：188–251 s ⇒ 单频点约 **63–84 s**
- LT2 为 **7 频点/组合**：按线性外推约 **420–600 s/组合**（含几何+网格）
- **72 组合 × 7 频点** ⇒ **约 8–12 小时**墙钟（与工单"12–16 小时理想 / 18–25 小时保守"同量级，偏乐观端）
- 分批建议（待你确认）：每批 **12 组合**（约 1.5–2 h/批）⇒ 6 批，每批独立 server 生命周期 + 独立 `run-id` + 聚合

## 6. 另附一条非阻塞事实（与当前主线无关，但影响未来 45 MHz 计划）

LT0-E 的 `fmax` 表达式预判实测 `[实测]`：mesh `size` 特征的 `hmax = "2.0E-5"`（**字面量 20 µm**，不是 `lamda/5` 形式），
且 `fmax` 35→45 时后处理求值未反映变化（很可能是**走旧解数据集**导致探针无效）。
⇒ **"改 fmax 即得到 45 MHz 新网格"这一前提尚未被证实**；将来若重启 45 MHz 路线，应先做
"改 fmax → 重建网格 → 比较单元数/统计"的重测。**本轮按用户指示不做 45 MHz，故不阻塞。**
