## 3. 排名报告中必须纠正的两处问题

### 3.1 “`(0.7,5)` 是唯一双带宽闭合点”不成立

从实际 `03_coarse_sweep_metrics.csv` 复核：

- 全部 72 组中，`bandwidth_closed_Vave == True` 且 `bandwidth_closed_Ptot == True` 的组合共有 **9 组**；
- 16 个 Pareto 组合中，同时满足两项闭合的共有 **3 组**：

| 组合 | FBW_Vave (%) | FBW_Ptot (%) | 15–25 MHz 平坦度 (dB) |
|---|---:|---:|---:|
| `(0.65,5)` | 52.95 | 72.79 | 2.75 |
| `(0.7,5)` | **54.88** | 63.64 | **1.61** |
| `(0.7,6)` | 54.00 | 55.70 | 3.70 |

因此可以写：

> `(0.7,5)` 是 Pareto 双带宽闭合候选中，兼顾较大 `FBW_Vave` 与较好 15–25 MHz 平坦度的代表点。

不得再写“唯一同时取到 `Ptot` 与 `Vave` 上下界”。

### 3.2 实际精扫产物仍是旧计划，禁止直接执行

目前实际文件 `final_phase2_ranking/05_fine_sweep_plan.csv` 仍为：

这与最新简报提出的 4–5 组、5–45 MHz、81 点不一致。**旧 `05_fine_sweep_plan.csv` 不得作为执行输入。** 在精扫前必须重新生成计划文件，并让 CSV、Markdown、manifest 和运行参数四处一致。

此外，`analyze_sweep.py` 当前会自动选“`Vave` 闭合组中 FBW 最大者”，所以选中了 `(0.75,2)`；这并不等于它是综合性能最优点。该点虽然 `FBW_Vave ≈ 124%`，但 `Ptot@20MHz ≈ 5.11e-7 W`，仅约为基准的 **12.6%**，且 `Ptot` 带宽没有闭合。它可作为“纯宽带、低输出”研究点，但不进入本轮主精扫名单。

## 5. 精扫前置门槛：先完成端口与 `Zin2` 取证

### 5.1 为什么必须先做

已知 `Zin2 = v0/I01` 的表达式不能证明第二端口阻抗，且可能只是重复使用第一端口电流。如果内外电极的实际复电位、支路电流方向或驱动幅相与预期不同，那么 405 个频点即使收敛，也只能代表“当前电路接法”，不能被解释为目标反相驱动结果。

### 5.2 最小取证任务

优先读取既有解，避免不必要重算。至少对基准 `(0.6,4)` 的 5、20、35 MHz 输出：

- 内电极实际复电位；
- 外电极实际复电位；
- `I01`、`I02` 的复数值；
- 每个电流变量的正方向定义；
- 端口电压差及幅相差；
- 当前 `Zin1`、`Zin2` 的完整表达式与单位。

先保存原始复数，不要只保存幅值。随后依据端口方程和电流正方向确定正确的 `Zin2`；在符号未确认前，不要直接把 `V/I02` 或 `-V/I02` 写成最终公式。

### 5.3 放行条件

只有在以下内容均写入审计报告后，才能启动第一阶段精扫：

- 两个电极的实际幅值和相位与当前驱动口径一致；
- `I01` / `I02` 的端口归属与正方向已确认；
- `Zin2` 不再错误引用 `I01`，或明确声明本轮不使用 `Zin2` 作任何筛选结论；
- 本轮精扫究竟研究“当前电路电流模型”还是“理想反相恒压驱动”已明确。若需要改变驱动物理定义，应另建模型版本和结果目录，不能覆盖当前模型证据链。
