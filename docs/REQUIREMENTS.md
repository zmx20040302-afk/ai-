## 1. 目标（一句话）

基于 DeepSeek Harness 构建 **MEMS/PMUT 仿真–数据–AI 闭环平台**：平台自主运行 COMSOL、自主扩充数据、训练 AI 模型，
并**在既定范围内以 AI 求解器替代 COMSOL 出场解**；模型可通过实验数据、文献数据与人反馈持续增强。

**来源**：用户原话「我想基于 deepseekharness 开发一个 mems 仿真自动化平台」+「我希望 ai 可以替代求解器的功能，
通过多次运算迭代，可以在不调用 comsol 的前提下完成求解，可以借助 comsol 进行验证」。

## 4. 硬性约束（不可协商）

1. **没有证据就不出数字**：每个数值可回溯到 `run_id` / 文献页码 / 实验 / 反馈。
2. **物理正确性优先**：守恒/边界/对称/极限不过关的解一律作废，**哪怕与数据吻合**。
3. **人保留放行权**：结构修改、模型晋升、超出范围的自动决策都需人工确认。
4. **免求解器必须有界**：带误差界 + S 级验证状态 + 适用范围判定；超范围拒答回退。
5. **来源永不混同**：`source_type` 六种（含 `ai_solver`），AI 解不得伪装成 COMSOL 解。
6. **历史 append-only**。
7. 中文文档；SI 单位 + `pint` 校验。
8. **改动计划文档与代码前需用户审批**（用户明确要求）。

## 5. 一个月交付"场级免求解器"的路径（关键决策）

用户要求初步模型**必须包含场级免求解器**。按深度学习算子（FNO/GNO/DeepONet）估算需 8–10 周；
但结合已确认条件——**固定拓扑 + 仅 1–2 个参数 + 单次 <5 min**——场解落在一个**低维流形**上，
因此改用**降阶（ROM/POD）优先**的路径，一个月内可行：

```
固定规则网格导出场快照（30–60 个点，每点 <5 min → 2.5–5 h 求解）
  → 减去均值得到波动场 → POD 基（能量占比 ≥99.9%）
  → 基系数对参数回归（GP / Kriging / 多项式）
  → 预测：场 = 均值 + Σ aᵢ(θ)·φᵢ(x)
  → 留出场算相对 L2（= S1 的 X） → 误差界用回归后验/保形预测
  → 物理一致性自校验（守恒/边界/对称/极限）→ 通过才放行
```

**为什么这条路更快**：训练在 CPU 上分钟级完成（不吃 6 GB 显存）；所需样本量比算子学习低一个量级；
基函数有物理可解释性，便于论文表述与误差归因。

**三个必须满足的前提（W1 确认）**

| # | 前提 | 说明 | 状态 |
|---|---|---|---|
| **P1** | **场快照可对齐到公共点集** | 用户要改**几何尺寸** → 网格随参数变化 → 快照必须落在**同一批固定坐标点**上，否则 POD 无法进行 | ✅ **2026-09-11 实测验证通过**（证据 `work/reports/p1_field_grid.json`）：公共点集固定 713 点；**材料参数变化与几何参数变化（重建几何+网格）后快照均等长**；几何缩小后有 **92 个域外点变为 NaN**，需掩膜处理。实现路线改为 **Python 侧插值**（取节点坐标+场值 → 插值到公共点集）——实测 COMSOL 的 Grid 数据集被 Eval 拒绝、插值数据集在 API 上下文无法创建、Export(location=grid) 网格定义不生效，故不采用 |
| P2 | **拓扑固定**（或限定在预先批准的结构变体清单内） | 每个变体单独训练一个流形/模型 | 待用户给变体清单（Q3） |
| P3 | **参数范围有限** | 超出范围 → 拒答 + 回退 COMSOL | 设计完成 |

**与 FNO/DeepONet 的关系**：降阶路径是"参数低维"场景的**更优起点**，不是替代品；当参数增多或拓扑变化时升级到算子学习
（P4.5 扩展）。两者共用同一套数据契约与验证门禁，因此后续升级不浪费前期工作。

## 6. "工作模式"落地方式（已核实）

DSH 原生支持 **agent preset**（界面上的「标准模式 / PTC 模式」选择器），本机已装 `@deepseek-ai/dsh-agent-presets`：

- 一个模式 = 一个目录，含 `preset.yml`（显示名/描述/排序）+ `agent.cordis.yml`（该模式挂载哪些插件）
- 用户目录 `USER_PRESET_DIR = '.agent-presets'`；GUI 提供 `list/select/read/copy/remove` 接口
- **做法**：在 GUI 里复制「标准模式」→ 改名「**MEMS 模式**」→ 把 `agent.cordis.yml` 换成 MEMS 组合：
  挂载 MCP（`mcp__mems__*`）、技能库、平台 persona 与红线
- 结果：用户在界面上选「MEMS 模式」即进入平台工作模式，其他模式不受影响；**不需要改 DSH 源码**
