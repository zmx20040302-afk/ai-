## 一、已经实现、而且真机验证过的

| # | 能力 | 现在的实际情况 |
|---|---|---|
| 1 | **改参数 → 重算 → 出结果** | 给一组参数，自动重建几何 → 重划网格 → 跑 7 个频点 → 取 7 行结果 → 自检 → 存档 → 关 COMSOL。**全程不用人盯** |
| 2 | **一组参数约 13–14 分钟** | 求解本身 12.7 分钟，加装模型/划网格/存档/清理 |
| 3 | **每组参数用独立 COMSOL 实例** | 组合之间互不污染（绕开了「一个进程只能连一个 COMSOL」的限制） |
| 4 | **求解后的完整交付** | 7 行结果 + 几何/选择集自检 + 原子存档 + 清理 + 确认端口释放（这条**第一次完整跑通**是在今天） |
| 5 | **内存实时监控 + 自动刹车** | 每 5 秒记录，越线就终止**自己那个** COMSOL。真机演练验证：**你桌面开着的 COMSOL 界面全程没被碰** |
| 6 | **不该跑时拒绝跑** | 内存不够、端口被占、代码版本被改过 → 一律拒绝启动，**不会偷偷降低标准硬跑** |
| 7 | **文件/版本防伪** | 每次运行都被「冻结」并逐字节校验；跑完再验一次，改动即作废（今天靠它抓出多次"偷偷改了代码"） |
| 8 | **偶发崩溃可复现** | 把之前"跑 7 次坏 1 次"的崩溃**变成必然复现并找到根因**，已修复并验证（同一压力下 7/80 → 0/80） |
| 9 | **已有数据的分析** | 你导出的 1134 行数据能质检、排名、算 Pareto、和另一批做对照 |
| 10 | **内存问题已解决** | 页面文件调整后，求解期内存余量从 647 MB 升到 17,410 MB（**27 倍**） |
| 11 | **平台侧** | 数据契约可机器校验（8 个 schema，8 合法/17 非法样例）；MCP 加了路径校验；`pytest` 恢复（240 个通过） |

## 三、你需要做什么

### 现在：**什么都不用做**，等它改完 F3、我建好新冻结。

### 接下来会需要你的两件事

1. **重跑演练前：腾内存**
   关掉游戏和多余程序，回到 **可用物理内存 ≥ 18 GB、commit 可用 ≥ 21.5 GB**。
   上次你关了 League 就达标了。**不达标它会拒绝跑**（这是设计，不是故障）。
   注意：**别关正在看这个对话的浏览器窗口**，也别关掉本会话（那是基础设施）。

2. **两个需要你拍板的决定**（不急，等前面收口后再定）
   - **要不要把频率扩到 45 MHz**：扩了带宽指标才有意义，但会**作废现有结果的可比性**（网格变了要重算），而且你说过你手头**没有 45 MHz 数据**；
   - **504 点生产批次什么时候开跑**：约 15–17 小时，建议**过夜**跑。

### 不需要你操心的

内存刹车、误杀保护、版本防伪、拒绝带病启动、失败现场保留、历史记录只增不改——**这些都是自动的，已经验证过**。
