## 0. 审阅结论

批2的1134行数据在表格完整性和数值可解析性方面合格，可以作为粗扫数据库。但当前还不能直接用于发布“最优参数”，主要原因如下：

1. `N_w_te1=1…18` 中包含明显超出原双电极设计顺序的参数；
2. 简报中的“约40/162可能 clean”来自圆柱选择包络估计，不能等同于实体电极几何结论；
3. 原预检脚本的面积计算依赖 `model.evaluate("intopN(1)")`，只构建几何和网格时可能读取失败或旧数据；
4. 面积读取失败后，原脚本仍可能将组合分类为 `clean`；
5. 35 MHz顶边比例被 `N_w_te1>=9` 的非设计区间明显放大；
6. `Zin2=v0/I01` 是复制错误，但 `v0/I02` 也不能在未确认实际端口电压和电流方向时直接认定为最终物理定义。

两份待审简报的SHA256完全相同，是同一份内容。建议以 `memsharness/docs/TO_CODEX_brief-20260913-batch2.md` 为主文件，另一份只作为冻结副本，避免以后出现双份内容不一致。

## 1. 立即执行的安全措施

当前后台守望任务会在COMSOL GUI退出后自动启动预检。在修正预检程序前，不应让该任务进入正式执行阶段。

原预检程序有以下需要先修复的问题：

### 1.1 面积计算不能依赖已有解

当前实现：

```python
model.evaluate("intop4(1)")
model.evaluate("intop3(1)")
model.evaluate("intop5(1)")
```

`model.evaluate` 通常通过现有结果数据集求值。若本轮只构建几何和网格、不运行求解器，它可能：

- 没有可用数据集而失败；
- 读取模型中保存的旧解；
- 返回与当前参数几何不对应的结果。

应改为COMSOL几何实体测量接口，直接根据当前边界实体编号计算面积，不依赖频域解。

### 1.2 面积读取失败不得判为 clean

必须新增分类：

```text
area_unavailable
```

只要任一必要面积为 `None`、非有限数或测量异常，该组合不得进入 `clean`。

### 1.3 预检分两级执行

第一级对162组全部执行：

```text
设置参数
→ 构建最终几何
→ 读取物理场实际使用的边界实体
→ 读取命名选择实体
→ 检查空集、交集和选择一致性
→ 用几何接口测面积
→ 立即写入checkpoint
```

第二级只对物理合理且第一级通过的组合执行网格构建。不要默认对162组逐一运行完整网格。

### 1.4 工程健壮性

预检程序还应增加：

- 每完成一个组合立即写JSONL或CSV checkpoint；
- `--resume` 断点续跑；
- 单组合异常捕获，不能因一个点失败而丢失此前全部结果；
- `try/finally` 释放模型、客户端和COMSOL server；
- 命名选择实体与物理边界条件实体的一致性比较；
- 面积随参数的跳变检查；
- 守望脚本实时流式写日志，不要在子进程结束后一次性写入。

## 2. Q1：`N_w_te1` 扫到18如何处理

采用“162组全量轻预检 + 物理范围内排名”的混合方案，不补扫更大 `x_scale`。

### 2.1 静态几何证据

模型实体构造包含：

```text
r6.size = N_w_te1*W_min
r7.size = N_w_te2*W_min
N_w_te2 = 9
sca1.anisotropic = {x_scale, 1, 1}
```

`r6` 和 `r7` 在生成后一起经过 `x_scale` 缩放。因此，实体内外顺序的核心条件是：

```text
N_w_te1 < N_w_te2 = 9
```

这个顺序条件本身不随 `x_scale` 改变。增大 `x_scale` 不能修复 `N_w_te1>=9` 导致的内外尺寸反序。

### 2.2 推荐参数分类

在 `W_min=4.2 µm`、`R_mem=42 µm`、`N_w_te2=9` 下：

| `N_w_te1` | 初步含义 | 是否进入主排名 |
|---|---|---|
| 1–8 | 原双电极设计的自然范围 | 通过实体预检后进入 |
| 9 | 内外设计边界重合，零间隔/退化 | 否，单独记录 |
| 10 | 内区超过外环起点并达到膜边缘 | 否 |
| 11–18 | 超过膜半径且内外顺序反转 | 否 |

所以批2的主候选区域为：

```text
9个x_scale × 8个N_w_te1 = 72组合
```

### 2.3 执行裁决

- 162组全部做成本很低的几何和实体选择预检，用于完整记录模型行为；
- 只对 `N_w_te1<=8` 且实体预检通过的组合做主排名；
- `N_w_te1>=9` 归入退化/越界设计附录，不进行昂贵精扫；
- 不追加更大 `x_scale` 批次，因为它不能恢复内外电极的正确半径顺序。

## 3. Q2：分类语义如何设计

建议新增独立分类，但不能继续使用原简报中随 `x_scale` 变化的圆柱包络公式，直接判定实体几何越界。

推荐分成以下状态：

| 分类 | 判据 | 含义 |
|---|---|---|
| `selection_envelope_warning` | `cyl8/cyl9` 辅助选择包络存在潜在相交 | 仅警告，不等于实体重叠 |
| `design_boundary_coincident` | `N_w_te1=N_w_te2=9` | 内外设计边界重合 |
| `design_region_reversed` | `N_w_te1>N_w_te2` | 内外设计半径顺序反转 |
| `physical_extent_suspect` | `N_w_te1*W_min>R_mem` | 物理特征尺寸疑似超过膜 |
| `bc_conflict` | 物理场实际边界实体集合存在交集 | 已确认边界条件冲突 |
| `geometry_out_of_bounds` | 最终实体检查确认超出膜或产生异常拓扑 | 已确认无效几何 |
| `clean` | 实体非空、无交集、面积有效、拓扑正常 | 可参与排名 |

原“40/162 clean”应改写为：

> 40组通过圆柱选择包络的保守估计条件；该计数不是最终实体几何 clean 数量。

## 5. Q4：35 MHz顶边数据还能支持什么结论

原始全162组统计为：

```text
Ptot峰值在35 MHz：83/162
Vave峰值在35 MHz：72/162
```

但该结果包含大量 `N_w_te1>=9` 的非设计组合，会放大顶边问题。

重新限制到 `N_w_te1<=8` 的72组后：

```text
Ptot峰值在35 MHz：19/72
Vave峰值在35 MHz：4/72
```

`Ptot` 峰值频率分布为：

| 峰值频率 | 组合数 |
|---:|---:|
| 10 MHz | 14 |
| 15 MHz | 11 |
| 20 MHz | 8 |
| 25 MHz | 8 |
| 30 MHz | 12 |
| 35 MHz | 19 |

因此批2仍然可以支持：

- 20 MHz固定频点响应比较；
- `x_scale`、`N_w_te1` 对响应的粗略趋势；
- 筛除明显低响应结构；
- 识别可能的多峰结构；
- 选择精扫候选。

但5 MHz频率间隔不足以精确报告 −6 dB 带宽，35 MHz峰值点也不能声称已找到完整谐振峰。

### 精扫建议

对最终3–5个候选直接使用：

```text
range(5[MHz],0.5[MHz],45[MHz])
```

共81个频点。

模型当前网格参数使用：

```text
fmax = 35[MHz]
lamda = c_water/fmax
hmax = lamda/5
```

精扫到45 MHz前，必须同步把有效 `fmax` 改为45 MHz并重建网格，或者完成等效的45 MHz网格收敛检查。否则45 MHz段不能继续声称满足约5单元/波长。

## 6. Q5：预检用哪个模型

接受使用98.9 MB的 `b_GE_task3_2new.mph` 做预检，不要求用7.93 GB保存态全量预检。

理由：

1. 批2 xlsx元信息记录的运行模型就是 `b_GE_task3_2new.mph`；
2. 预检只需要参数、最终几何、选择和网格定义，不需要保存的1134组频域解；
3. 轻模型加载和重复构建成本远低于7.93 GB保存态；
4. 脚本本身会建立只读副本并记录源文件哈希。

合规条件：

- 记录轻模型完整SHA256；
- 记录staged copy SHA256；
- 记录COMSOL版本；
- 确认最终有效参数赋值；
- 至少保存 `(0.4,1)`、`(0.6,4)`、`(0.8,8)` 等哨兵点的实体编号和面积；
- 大模型解锁后只需做1–3个哨兵点交叉验证，无需再跑全部162组。

简报中的“几何/选择/参数逐项一致”建议改成更严谨的表述：

> 在当前 `.m` 提取器覆盖的参数、几何、选择、物理场、网格和求解器导出语句中未发现差异。

`.m`静态diff不能证明两份`.mph`中的保存态解、缓存、网格实体和结果数据集完全一致。

## 8. Q7：`Zin2` 是否现在修

### 8.1 复制错误可以确认

当前：

```text
I01 = intop3(es.JZ)
I02 = intop4(es.JZ)
Zin1 = v0/I01
Zin2 = v0/I01
```

`Zin2`重复使用`I01`属于明确的复制错误。

### 8.2 不能直接确认 `v0/I02` 是最终物理定义

外电极由Circuit Terminal驱动，其实际复电位不一定等于参数`v0`。因此更合理的候选定义是：

```text
Z_outer = V_outer_actual/I_outer
```

符号由COMSOL终端电流正方向决定。如果研究的是内外电极差分输入，则应进一步考虑：

```text
Z_diff = (V_outer_actual - V_inner_actual)/I_port
```

### 8.3 执行裁决

先利用已有解导出5、20、35 MHz的：

```text
V_inner_complex
V_outer_complex
I01
I02
V_outer/I02
-V_outer/I02
V_outer-V_inner
```

用端口电流方向、输入有功功率方向和阻抗实部合理性确定符号。

在最终定义确认前：

- 旧`Zin2`保留并标记`known_formula_bug`；
- `Zin2`不参加排名；
- 精扫前固定正确的端口定义和导出表达式。

只修改后处理变量`Zin2`不会影响`Ptot`或`Vave`，并且通常可以直接用已有解重新求值，不必重跑物理解。如果同时修改Circuit、Terminal或电极驱动方式，则所有响应必须重新求解。

## 9. 对参数 Diff 结论的审阅

“本轮只修改了扫描区间，没有修改37个全局参数的定义和物理模型”这一总体结论可以接受，但建议注意以下表述：

1. 必须区分“37个唯一全局参数名”和“.m文件中的重复赋值语句数”；
2. 同一属性存在多次赋值时，以最后一次有效赋值为准；
3. `setIndex`、`setEntry`、`active`、`remove`、`move`、`selection.named` 等操作都必须纳入diff；
4. “没有发现差异”应限定为提取器覆盖的导出语句，不应扩大为两份二进制`.mph`完全等价；
5. 新增结果表、EvalGlobal和保存文件路径不会改变物理解，但会改变输出和文件保存状态。

建议在diff报告中同时给出：

```text
unique_effective_properties
assignment_statement_count
overwritten_assignments
final_effective_value
source_line
```
