### 1.1 第 3 项的实测结论（**如实报，不粉饰**）

主判定折 `L-N2ex(8)`（训练 N2∈{5,6,7} → 测试 **N2=8**，即外部增量层）：

| 通道 | 正式目标 | 覆盖率 | 中位(log10) | p90 | 抄相邻层(中位) | 增益 | 判定 |
|---|---|---|---|---|---|---|---|
| `abs_p_per_V_Pa` | 是 | 69.8% | 0.0016 | 0.0037 | 0.0045 | **+0.0029** | pass |
| `abs_p_Pa` | 否 | 69.8% | 0.0016 | 0.0037 | 0.0045 | +0.0029 | pass |
| `abs_w_m` | 是 | 69.8% | 0.0026 | 0.0081 | 0.0054 | +0.0028 | pass |
| `abs_vz_struct_m3s` | 否 | 69.8% | 0.0026 | 0.0059 | 0.0054 | +0.0028 | pass |
| `f_peak_Hz` | 否 | 69.8% | 0.0000 | 0.0073 | 0.0000 | 0.0000 | pass |
| `bandwidth_Hz` | 是 | 73.2% | 0.0050 | 0.0441 | **0.0032** | **−0.0018** | pass |
| `Q_factor` | **否（只作门槛）** | 73.2% | 0.0035 | 0.0323 | **0.0025** | **−0.0010** | pass |
| `peak_SPL_dB` | 否 | 69.8% | 0.0310 | 0.0745 | 0.0892 | +0.0582 | partial |

**三条必须一起读的要点**：

1. **8 个通道里 2 个「未优于持续性基线」**（`bandwidth_Hz`、`Q_factor`）：
   它们的**绝对精度过了预注册带**，但**不如直接抄相邻层**——
   即模型在这两个量上**没有增值**，工程上直接用相邻层即可。
   报告与 JSON 都**点名列出**（`channels_without_lift`），并有专门用例锁住「不得只报 pass」。
   *原因*：这两个量的层间差异本身很小，而线性外推要估一个斜率，斜率噪声反而更大。
2. **覆盖率只有约 70%**，是**结构性拒答**而非 bug：C 的每层 N1 上限 = N2−1，
   故 N2=8 的 `N1=7` 在训练层里**根本不存在**（`no_layer_for_n1`）；
   `N1=6` 在训练层里**只有一层**（`need_two_layers_to_extrapolate`），单点无法线性外推。
   提高覆盖率需**换模型**（跨 N1 借斜率）⇒ 必须**另开一版预注册**，不在本版事后改。
3. **`f_peak_Hz` 中位恰为 0.0000，不是「极准」**：它只有 87 个离散取值（0.5 MHz 量化），
   且实测 **86.6% 的组合在 N2=7 与 N2=8 上完全相同** ⇒ 斜率≈0、退化为「抄上一层」。
   属**易预测但区分度低**，排名时不应据此下强结论。

**预注册不可事后改**已用机械手段锁住：结果 JSON 记录预注册文件 sha256，
用例断言「当前哈希 == 记录哈希」，改了判定带立刻失败。

**关键自检**：新报告的 ① 项**由重算得到**并与历史 JSON **逐位一致**
（`recompute_matches_history = True`，median/p90/max 差值 < 1e-9）——
即 ④ 与 ①② 同源自洽，不是另算一套。

**顺带发现（写进报告）**：R-CB-N28 的测试集**确实含**角点 `(0.2,1,8)`，
且它正是本折**最差组合**：|ΔSPL@20 MHz| = **0.4932 dB**，而**谱内 max |Δ| = 8.15 dB**。
⇒ 此前"20 MHz 标量一致性极好（0.000/0.493 dB）但整条谱 max 差 8.15 dB"这一现象，
现在在一份固定格式报告里**同时可见**，不会只报标量而给人「两批完全一致」的错觉。
